Overview

Recommended message split

Marketing pages should talk about the native PowerBuilder runtime interface or ORCA API. Technical docs can document the exact runtime requirements and environment variables because developers need that level of precision.

From your public repo I confirmed the operational flow is driven by environment variables like PB_WORKSPACE_DIR, PB_ORCA_PATH, PB_MCP_LICENSE, PB_MCP_LICENSE_API_URL, and PB_MCP_MACHINE_CODE, with a PowerShell entrypoint in run_mcp.ps1.
Step 1

Install prerequisites

  • Windows environment compatible with your PowerBuilder runtime
  • GitHub Copilot in VS Code or another MCP-capable client
  • PowerBuilder workspace available locally
  • PowerBuilder MCP binary/release package
PowerShellrun_mcp.ps1
$WorkspaceDir = "C:\projects\sales_app"
$OrcaPath     = "C:\path\to\native\runtime"
$LicenseKey   = "PBMCP-XXXX-XXXX-XXXX"

powershell -ExecutionPolicy Bypass -File .\run_mcp.ps1 `
  -WorkspaceDir $WorkspaceDir `
  -OrcaPath $OrcaPath `
  -LicenseKey $LicenseKey
Step 2

Configure Copilot MCP

For the public website, I’d show a realistic configuration block instead of fake install fluff. The exact shape may vary by client version, but the concept is: register a local stdio MCP server and pass the workspace/runtime environment.

settings.jsonconceptual example
{
  "github.copilot.chat.mcp.servers": {
    "powerbuilder": {
      "command": "powershell",
      "args": [
        "-ExecutionPolicy", "Bypass",
        "-File", "C:\\PowerBuilderMCP\\run_mcp.ps1"
      ],
      "env": {
        "PB_WORKSPACE_DIR": "C:\\projects\\sales_app",
        "PB_ORCA_PATH": "C:\\path\\to\\native\\runtime",
        "PB_MCP_LICENSE": "PBMCP-XXXX-XXXX-XXXX"
      }
    }
  }
}

Reference

Actual tool surface from the public repo

  • list_libraries — enumerate available PBL libraries
  • list_objects — inspect objects in a specific library
  • export_object — export an object into analyzable source
  • import_object — compile/import source back into a library
  • search_objects — search by pattern and optional object type
  • parse_datawindow — extract SQL/tables/columns from exported DataWindows
  • analyze_dependencies — identify object/function references
  • find_nested_datawindows — locate nested DW usage
Support

Troubleshooting notes worth documenting

  • The PowerBuilder runtime path must be valid on the local machine.
  • Your repo explicitly checks process architecture compatibility; document that clearly in the compatibility section.

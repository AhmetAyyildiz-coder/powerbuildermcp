Capabilities

Use real PowerBuilder operations,
not fake AI intuition

I checked your public repo and aligned the messaging to actual MCP tools already present in the product: list_libraries, list_objects, export_object, import_object, search_objects, parse_datawindow, analyze_dependencies, and find_nested_datawindows.

01

Workspace discovery

Enumerate libraries and objects so Copilot understands the actual PowerBuilder surface area before suggesting anything.

02

Source export

Export windows, DataWindows, user objects, structures, and functions into analyzable source for documentation and refactoring.

03

DataWindow intelligence

Parse exported DataWindows to extract SQL, tables, columns, nested DataWindows, and retrieval arguments.

04

Dependency mapping

Trace calls to functions, user objects, and shared utilities before touching high-risk legacy flows.

05

Search at product scale

Search libraries and object names across a large codebase to find dead zones, duplicates, and modernization candidates.

06

Controlled write-back

Support import workflows for teams that want AI-assisted edits in a governed, reviewable process.

Positioning

My recommendation: product site first, resource site second

If you may sell this, don’t lead with a community-resource identity. Lead with a serious product posture, then attach educational content underneath it.

  • ✓Homepage: clear problem, realistic UI, enterprise trust, call to docs/demo/contact.
  • ✓Docs: install, configure, verify, troubleshooting, compatibility.
  • ✓Prompt library: example prompts by use-case — analysis, DataWindow audit, dependency tracing, migration prep.
  • ✓Later: case studies, blog, pricing, licensing, download portal.

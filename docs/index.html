Overview

How it works

PowerBuilder MCP runs as a local stdio server that bridges your PowerBuilder workspace to MCP-compatible AI clients like GitHub Copilot. No source code leaves your machine.

The server is configured via environment variables: PB_WORKSPACE_DIR, PB_ORCA_PATH, PB_MCP_LICENSE, PB_MCP_LICENSE_API_URL, and PB_MCP_MACHINE_CODE, with a PowerShell entrypoint in run_mcp.ps1.
Step 1

Install prerequisites

  • Windows environment compatible with your PowerBuilder runtime
  • GitHub Copilot in VS Code or another MCP-capable client
  • PowerBuilder workspace available locally
  • PowerBuilder MCP binary / release package
PowerShellrun_mcp.ps1
$WorkspaceDir = "C:\projects\sales_app"
$OrcaPath     = "C:\path\to\native\runtime"
$LicenseKey   = "PBMCP-XXXX-XXXX-XXXX"

powershell -ExecutionPolicy Bypass -File .\run_mcp.ps1 `
  -WorkspaceDir $WorkspaceDir `
  -OrcaPath $OrcaPath `
  -LicenseKey $LicenseKey
Step 2

Configure Copilot MCP

Register PowerBuilder MCP as a local stdio server in your Copilot settings.

settings.jsonVS Code → Copilot
{
  "github.copilot.chat.mcp.servers": {
    "powerbuilder": {
      "command": "powershell",
      "args": [
        "-ExecutionPolicy", "Bypass",
        "-File", "C:\\PowerBuilderMCP\\run_mcp.ps1"
      ],
      "env": {
        "PB_WORKSPACE_DIR": "C:\\projects\\sales_app",
        "PB_ORCA_PATH": "C:\\path\\to\\native\\runtime",
        "PB_MCP_LICENSE": "PBMCP-XXXX-XXXX-XXXX"
      }
    }
  }
}
Step 3

Verify the connection

Run a smoke test to confirm the MCP server initializes correctly.

PowerShellsmoke test
powershell -ExecutionPolicy Bypass -File .\run_mcp.ps1 -SmokeTest

# expected outcome:
# initialize request succeeds and the MCP server responds

Then open Copilot Chat and ask a low-risk discovery question like "list libraries in this workspace" before trying heavier analysis prompts.

Reference

Tool reference

  • list_libraries — Enumerate available PBL libraries in the workspace
  • list_objects — Inspect objects in a specific library
  • export_object — Export an object into analyzable source format
  • import_object — Compile or import source back into a library
  • search_objects — Search by pattern and optional object type
  • parse_datawindow — Extract SQL, tables, and columns from exported DataWindows
  • analyze_dependencies — Identify object and function references
  • find_nested_datawindows — Locate nested DataWindow usage
Support

Troubleshooting

  • The PowerBuilder runtime path must be valid on the local machine.
  • Check process architecture compatibility (32-bit vs 64-bit).
  • Verify your license key is valid and not expired.
  • Ensure PB_WORKSPACE_DIR points to a valid .pbw file.
